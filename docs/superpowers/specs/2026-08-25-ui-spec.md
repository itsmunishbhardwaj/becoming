# UI & Next.js Structure Spec — Becoming

**Part of:** Supabase + Next.js migration  
**Depends on:** `2026-08-25-api-spec.md`  
**Status:** Draft — awaiting approval before any code is written

---

## 1. Design decisions

### All screens stay as client components

Every screen has interactive state (useState, useEffect, event handlers, store
calls). All get `'use client'` at the top. No server-side data fetching for now
— same pattern as today, just on Next.js instead of Vite. This keeps the port
mechanical and avoids introducing async server component complexity.

The root layout (`app/layout.jsx`) is a server component — it only renders
HTML shell, fonts, and meta. Everything inside `<body>` is client-rendered.

### Components port verbatim

All components in `src/components/` use inline styles and no framework
dependencies. They move unchanged to `src/components/` in the Next.js project.
No rewrites needed.

### react-router-dom is deleted

Every import from `react-router-dom` is replaced with its Next.js equivalent.
See §4.

### Vite entry point deleted

`App.jsx`, `main.jsx`, `index.html`, `vite.config.js` are deleted.
`next.config.js` replaces them.

## 2. App Router file structure

```
app/
  layout.jsx               ← root layout: HTML shell, fonts, global styles, PWA meta
  page.jsx                 ← / → Home screen
  year/
    page.jsx               ← /year → Year screen
  month/
    [yyyymm]/
      page.jsx             ← /month/:yyyymm → Month screen
  week/
    [yyyymmdd]/
      page.jsx             ← /week/:yyyymmdd → Week screen
  day/
    [date]/
      page.jsx             ← /day/:date → Day screen
  goal/
    [id]/
      page.jsx             ← /goal/:id → Goal workspace screen
  onboard/
    page.jsx               ← /onboard → Balboa Breakdown wizard
  create/
    page.jsx               ← /create → QuickCreate
  (auth)/
    login/
      page.jsx             ← /login → Google sign-in
    auth/
      callback/
        route.js           ← /auth/callback → OAuth exchange (API route, not a page)

src/
  components/              ← unchanged; all port verbatim
  screens/                 ← unchanged; each screen exported and re-used as-is
  data/                    ← unchanged; supabaseStore added
  lib/
    supabase/
      client.js
      server.js
  tokens.js                ← unchanged
  ...

public/                    ← unchanged; icons and manifest carry over
middleware.js              ← auth guard (see API spec §4)
next.config.js
```

The `app/` pages are thin wrappers — they import and render the existing screen
component. All logic stays in `src/screens/`.

Example (`app/page.jsx`):
```jsx
'use client'
import Home from '../../src/screens/Home.jsx'
export default function HomePage() { return <Home /> }
```

This keeps screen files testable and framework-agnostic. Tests continue to
import from `src/screens/` directly.

## 3. Root layout — `app/layout.jsx`

Replaces `index.html`. Server component (no `'use client'`).

```jsx
import { Fraunces, Inter } from 'next/font/google'

const fraunces = Fraunces({
  subsets: ['latin'],
  weight: ['400', '500', '600'],
  variable: '--font-fraunces',
  display: 'swap',
  axes: ['opsz'],
})

const inter = Inter({
  subsets: ['latin'],
  weight: ['400', '500'],
  variable: '--font-inter',
  display: 'swap',
})

export const metadata = {
  title: 'Becoming',
  themeColor: '#FBFBF9',
  manifest: '/manifest.webmanifest',
  appleWebApp: {
    capable: true,
    title: 'Becoming',
    statusBarStyle: 'default',
  },
  icons: {
    apple: '/icon-180.png',
    icon: [
      { url: '/icon.svg', type: 'image/svg+xml' },
      { url: '/icon-192.png', type: 'image/png' },
    ],
  },
}

export default function RootLayout({ children }) {
  return (
    <html lang="en" className={`${fraunces.variable} ${inter.variable}`}>
      <head />
      <body>
        {children}
      </body>
    </html>
  )
}
```

Global styles (from `index.html` `<style>` block) move to `app/globals.css`:
```css
html, body { margin: 0; min-height: 100%; overflow-x: hidden; }
body {
  background: #FBFBF9;
  padding: env(safe-area-inset-top) env(safe-area-inset-right)
           env(safe-area-inset-bottom) env(safe-area-inset-left);
}
* { box-sizing: border-box; }
```

Import in layout: `import './globals.css'`

**Font note:** The current `index.html` loads fonts via a Google Fonts `<link>`
tag. `next/font/google` downloads them at build time and serves them locally —
no external request, better performance, no FQDN reference needed.

## 4. react-router-dom → next/navigation migration

Every import from `react-router-dom` is replaced. Full table:

| react-router-dom | next/navigation / next/link | Notes |
|------------------|-----------------------------|-------|
| `useNavigate` → `nav('/x')` | `useRouter` → `router.push('/x')` | Import from `next/navigation` |
| `useParams` → `{ id }` | `useParams` → `{ id }` | Same API, different import |
| `useSearchParams` → `[params]` | `useSearchParams` → `params` | Returns `ReadonlyURLSearchParams`; use `params.get('key')` |
| `Link` | `Link` from `next/link` | Same JSX API; `to=` → `href=` |
| `BrowserRouter`, `Routes`, `Route` | Deleted | App Router handles routing |

### Per-file changes

| File | What changes |
|------|-------------|
| `src/App.jsx` | **Deleted** |
| `src/main.jsx` | **Deleted** |
| `src/screens/Home.jsx` | `Link` → `next/link` |
| `src/screens/Year.jsx` | `Link`, `useSearchParams`, `useNavigate` → next equivalents |
| `src/screens/Month.jsx` | `Link`, `useParams`, `useSearchParams`, `useNavigate` → next equivalents |
| `src/screens/Week.jsx` | `Link`, `useParams`, `useSearchParams`, `useNavigate` → next equivalents |
| `src/screens/Day.jsx` | `Link`, `useParams`, `useNavigate` → next equivalents |
| `src/screens/Goal.jsx` | `Link`, `useParams` → next equivalents |
| `src/screens/Onboard.jsx` | `useNavigate`, `Link`, `useSearchParams` → next equivalents |
| `src/screens/QuickCreate.jsx` | `Link`, `useNavigate` → next equivalents |
| `src/components/GoalCard.jsx` | `Link` → `next/link` |

`useSearchParams` from `next/navigation` must be wrapped in `<Suspense>` when
used in a page component. Wrap the screen component in a Suspense boundary in
the `app/` page wrapper, or move the `useSearchParams` call into a
`'use client'` child component.

## 5. Screen-by-screen porting notes

### Home — `app/page.jsx` → `src/screens/Home.jsx`

No param reads. Only change: `Link` import.

### Year — `app/year/page.jsx` → `src/screens/Year.jsx`

Uses `useSearchParams` (reads `pen` param for selected goal) and `useNavigate`
(pushes to `/month/:yyyymm` on drill-down). Wrap in Suspense in the page file.

### Month — `app/month/[yyyymm]/page.jsx` → `src/screens/Month.jsx`

Uses `useParams` for `yyyymm`, `useSearchParams` for `pen`, `useNavigate` for
swipe nav. Wrap in Suspense.

### Week — `app/week/[yyyymmdd]/page.jsx` → `src/screens/Week.jsx`

Same pattern as Month.

### Day — `app/day/[date]/page.jsx` → `src/screens/Day.jsx`

Uses `useParams` for `date`, `useNavigate` for back navigation.

### Goal — `app/goal/[id]/page.jsx` → `src/screens/Goal.jsx`

Uses `useParams` for `id`. Only change: Link + useParams imports.

### Onboard — `app/onboard/page.jsx` → `src/screens/Onboard.jsx`

Uses `useSearchParams` (reads `goalId` and `turn` for edit mode) and
`useNavigate` (redirects after save). Wrap in Suspense.

### QuickCreate — `app/create/page.jsx` → `src/screens/QuickCreate.jsx`

Uses `useNavigate`. Straightforward.

## 6. Login page — `app/(auth)/login/page.jsx`

Styled to paper theme. No form, no email — one button.

```jsx
'use client'
import { createClient } from '../../../src/lib/supabase/client'
import { PAPER, TYPE } from '../../../src/tokens'

export default function LoginPage() {
  async function signIn() {
    const supabase = createClient()
    await supabase.auth.signInWithOAuth({
      provider: 'google',
      options: { redirectTo: `${window.location.origin}/auth/callback` },
    })
  }

  return (
    <main style={{
      minHeight: '100dvh',
      background: PAPER.bg,
      display: 'flex',
      flexDirection: 'column',
      alignItems: 'center',
      justifyContent: 'center',
      gap: 32,
      padding: '0 24px',
    }}>
      <div style={{ textAlign: 'center', display: 'flex', flexDirection: 'column', gap: 8 }}>
        <h1 style={{ fontFamily: 'var(--font-fraunces)', fontSize: 32, color: PAPER.ink, margin: 0 }}>
          Becoming
        </h1>
        <p style={{ fontFamily: 'var(--font-inter)', fontSize: TYPE.body, color: PAPER.dim, margin: 0 }}>
          Who are you becoming?
        </p>
      </div>
      <button
        onClick={signIn}
        style={{
          fontFamily: 'var(--font-inter)',
          fontSize: TYPE.body,
          color: PAPER.ink,
          background: PAPER.card,
          border: `1px solid ${PAPER.line}`,
          borderRadius: 999,
          padding: '12px 24px',
          cursor: 'pointer',
        }}
      >
        Continue with Google
      </button>
    </main>
  )
}
```

## 11. What this spec does NOT cover

- **Supabase wiring inside screens** — screens currently call `store.js`. After
  the data layer is implemented, `store.js` points to `supabaseStore`. Screens
  need no changes for data — only the router imports change.
- **Vault migration script** — covered in database spec §8. Runs once before
  going live.
- **Vercel deployment config** — covered in a separate deploy step; env vars
  are set in the Vercel dashboard.
- **Onboarding for new users (zero goals state)** — current empty state is a
  single card. Richer first-run experience is a follow-on.
